# TypeScript 6.0.3 to tsrs 7.1.0-beta.tsrs5 (2026-11-24)

The tooling's checker went from TypeScript 6.0.3 in process to tsrs (a port of TypeScript 7.1 beta, commit 3e92363). This
records what was compared, every difference, and what was decided. tsrs alone was used: no other TypeScript 7.

## What was compared, before any expected result was changed (none was)

| corpus | asked | same file, line and code | otherwise |
|---|---|---|---|
| the boundary checks of the drafts of the 193 coverage modules, every candidate reading | 305 files | 292 | 13: A (7), B (6) |
| the drafts themselves, with their causes | 193 | 193, byte for byte (after A's remedy) | |
| `ref/types` (245 programs, ref's projection and the crate's) | 2 × 245 | 2 × 245 | |
| `rx-tsc` on the 24+ tasks, every probe and variant | 163 runs | 162 | 1: C |
| `rx-tsc` on the coverage entries | 123 runs | 123 | |
| tsconfigs (`include` forms, removed options, node16, checkJs, declarations) | 17 | 12 | D, E |

## Differences

**A. Two identical generic signatures that write a conditional over their own type parameter are refused (TS2719, TS2322).**
Critical: a correct program is refused. Cause: TypeScript 7.1 beta, a regression of microsoft/TypeScript#64237 reported as
#64673 (milestone 7.1.1 RC), its fix #64307 open; tsrs reproduces its pin.

```ts
declare function f<T>(v: T): T extends any[] ? T[number] : NonNullable<T>;
const g: <T>(v: T) => T extends any[] ? T[number] : NonNullable<T> = f;   // 6.0.3: accepted
```

It took two rows of `@solid-primitives/utils` (`accessWith`, `asArray`) to `any` or to a type by its place, and refused one
row each of `keyed`, `utils/immutable` and (two readings) `@ui-sdk/solid`'s Slider. Two *instances* of such a type relate,
so the crate writes a row with a conditional as an instance (`type __decl_f<__Any = unknown> = <T extends __Any>…`,
project.rs `as_instance`); every draft is what it was, and a row that says another branch, condition or answer is refused
(test/checker.js, which also fails when the regression is gone). **What is left: an app's own code.** A `.rx` or `.ts`
program that assigns such a function to its own type, or the shape of #64892 (a value of `T` given to a parameter of type
`T extends string ? … (x: T) …`), is refused where TypeScript 6 accepted it. Nothing in the benchmark, the examples or
`scenarios/` writes one; Effect and vuejs/core do (the issue's comments). This is the one blocker.

**B. TS2589 ("excessively deep") is TS5114 ("Instantiations of type 'FeatureNames' appear infinitely circular").** Same file,
line and verdict (readings 6 and 8 of `@wardic/solid`, `/unstable/v2`, `/v1`). Cause: intended; TypeScript 7's checker names the
type at the same depth limit (checker.go `instantiateTypeWithAlias`; tsrs checker_11.rs). Not critical: a row is found by line.

**C. TS2740 on an alias of a generic class is TS2322 with TS2740's text beneath it.** Same line and column
(`router-code-routes`). Cause: intended; TypeScript 7 drops the head when the two messages print the same type names
(relater.go `reportRelationError`, `chainArgsMatch`), and 6 when the types are the same, which an alias is. Not critical.

```ts
class K<T> { a!: T; b!: T } type AK = K<any>; declare const r: { id: 1 };
const z: AK = r;   // 6.0.3: TS2739   7.1: TS2322, TS2739 beneath
```

**D. Options TypeScript 7 removed are errors:** `baseUrl` (TS5102, was TS5101 or silent under `ignoreDeprecations`),
`moduleResolution: node10` and `target: ES5` (TS5108). Intended (TypeScript 6's own message says so). Case by case: kept,
in CHANGELOG. Their place in the tsconfig.json is not said (the options are given to the API as values). Not critical.

**E. Under `nodenext`, `./api` with no extension in an `.rx` is TS2834 (was TS2307).** Same line, better reason: a projection is
now a file TypeScript knows the module format of. Not critical.

**F. Wording:** printed type order and elisions (20 of 286 runs' texts). Not critical.

No crash, hang, or answer that varied from run to run was seen: each of the 305 checks was asked twice.

## Splitting a check

The plan was to cut a draft's check into files so that checkers run in parallel. tsrs serves its API with one checker a
program, so files of one program are not checked in parallel, and programs of one process are not either (its requests are
served in turn): only processes are. `@ui-sdk/solid`'s 4.6 MB, one check: 0.84 s wall, 0.92 s CPU whole; 0.71 / 1.28 in two
processes; 0.61 / 1.9 in four. And the verdicts are **not** the same for any cut: over the 305 checks cut in 1, 2, 3, 4, 8 and 16,
303 are; two readings of `@ui-sdk/solid` lose a TS2589 (readings 6 and 8, one row each), because the depth limit is met or not
by what the checker has read before. TypeScript's own (tsrs's notes/open-history-dependence.md); 6.0.3 reports both whole.
So a check is never cut. (Whole candidate readings were checked in parallel workers for a day; *After the short drafts*, below,
says why that is gone.)

## What stays on TypeScript 6, and why

rx-declare's reading of a library's types and the parsing of JavaScript. A draft of `@ui-sdk/solid` makes 8.8 million calls of
the checker and its types (3.3 million `getNonNullableType`, 1.6 million `getCallSignatures`, 1.2 million `typeToString`); at
15 µs a request (8,200 file callbacks cost 120 ms) the six million that are not local are 90 s, where reading in process is 15 s. With the checks on tsrs it
is the larger share of a draft, but a port would first need those calls made few. Two checkers in one tool are sound here
because their work is in series: what 6 reads is text, and 7 holds it against the module or it is not written. Where they
differ the draft says less (as in A, before its remedy), never something false. In the editor the two are side by side (hover
by 6, errors by 7), and a hover may print what an error does not.

## useFieldControl (fixed)

`@ui-sdk/solid`'s useFieldControl row was not wrong about the library and no artefact of a setup. rx-declare drafted `{ name: ref
string | undefined; … } | null`, and `ref` under a union is no place the notation reads (MO-10b), so it reached TypeScript as
the text `ref string`: TS1005, TS1434 and then TS2322, in both checkers. solid-sonner's `toast.promise` had the same shape
(`{ unwrap: ref … } | undefined`), and fell to a row that said less. A record that may be absent is now drafted with functions
(`name: () => string | undefined`); no row of the 193 drafts holds a word the crate's check leaves in (test/declare.js).

## Content mappers

Prototyped (a node process answering `transform` with the crate's projection, `tsrs -p . --runExternalCode`): it checks
examples/shop in 0.09 s against rx-tsc's 0.16 s, and places an error rightly. Not taken: a mapper's spans may not overlap,
and the crate's do (a name within an expression, one expression twice), so its places would be fewer; a mapper cannot answer for
the `.d.ts` a `.d.rx` stands for (TY-4b); TY-6, the crate's rows and `--rx-inputs` still need rx-tsc, and the mapper is a
second process that analyzes the same modules; it must be named in the tsconfig and run with a flag. It is the way to a
TypeScript 7 editor or a plain `tsc` that reads `.rx`, once the crate has spans that do not overlap.

## Also found

- `Cursor::line` (parse.rs) counts newlines from the start of the file at each row: 11 of the 12 s the crate takes to read
  `@ui-sdk/solid`'s seven 4 to 8 MB candidates. One counter would remove it. Left to the run on speed.
- tsrs's API's `parseConfigFile` does not take `--runExternalCode`, so `.rx` cannot be an extension of the project there;
  src/program.js reads the globs over a view of the folders instead.

## After the short drafts (PR #1 at c3c9b88, merged 2026-11-24)

Compact rows, and a draft checked once whole and then in small parts. Compared again, with TypeScript 6.0.3 at c3c9b88:

| corpus | asked | same file, line and code | otherwise |
|---|---|---|---|
| every check of the 193 drafts | 210 | 207 | 3: A, as the crate there writes a row (none as this one does) |
| the drafts, with their causes | 193 | 193, byte for byte (before the drafter's fix above, which changes three) | |
| the same checks in one program under 1, 2, 4 and 8 checkers (tsrs's command line) | 204 | 204, the same 31 errors each time (6 with the drafter's syntax errors left out) | |
| `rx-tsc` on tasks, probes and coverage | 286 | 285 | 1: C |
| `ref/types` | 2 × 245 | 2 × 245 | |

B is not met any more: the readings that reached the depth limit are not made. No new difference.

The workers that checked candidate readings in parallel are removed: a draft is checked once, and the small checks after it
each depend on the one before, so nothing is left to run beside anything.
